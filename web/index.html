A Solana client written in Lean, compiled by its own compiler.

leansol joins Solana's gossip network and checks the signature on every record it hears. It is written in Lean 4 and turned into machine code by leanc, a compiler in the same repository that needs no libc, no LLVM and no linker. Its processes talk through shared memory and a single futex. It also runs on-chain programs: its sBPF virtual machine executes what toly's lean-svm compiles, lets those programs call the real SPL token programs, and applies whole signed transactions.

How it worksfour pieces, all in one repository

A compiler, an IPC layer, a node and a virtual machine

leanc: Lean in, ELF out

Reads Lean 4 source and writes the bytes of a static x86-64 executable itself: instruction encodings, jump fix-ups, ELF headers. No C is generated and no toolchain runs. Reference counting gives immutable Lean values in-place updates.

-- Lean
(x >>> n) ||| (x <<< (32 - n))
-- what leanc emits for rotr e 6
mov rax, [rbp-80]
ror eax, 6

IPC on a raw futex

Processes pass messages through lock-free rings in shared memory. Sending is a memory copy and one atomic add. The kernel is involved only when the receiver is asleep, and then through a single futex wake.

producer
lock xadd  head += 1
if sleeping: futex_wake
consumer
xchg  sleeping := 1
if empty:   futex_wait

Tiles: one job per process

Receiving, verifying, protocol logic and sending each run as their own process. Only records that passed verification ever reach the process holding the node's key.

socket ─▶ net-rx ─▶ verify × N
                        │
socket ◀─ net-tx ◀─── gossip
every arrow between processes is a ring

sBPF virtual machine

Loads on-chain programs and applies signed transactions to accounts: signatures, fees, compute budgets, programs calling programs, rent, every sysvar. Lean, Pinocchio and Anchor programs run against the unmodified SPL token programs, with results identical to Agave's runtime.

$ leansol run amm.so --data 01… \
    --program Token=p_token.so \
    --program Token-2022=spl_token_2022.so …

Capabilitieswhat works today

What it does

Joins gossip on mainnet, testnet and devnet

Resolves an entrypoint with its own DNS resolver, learns the cluster's shred version, and starts pulling records.

Verifies every signature

Strict Ed25519, the rules validators apply, written in Lean. About 2,900 checks per second per core.

Reads every record type

Knows the wire layout of all 14 gossip record types, so it can find where each record ends and who signed it.

Proves it owns its address

Answers the ping challenges peers send with signed pongs, as the protocol requires before anyone replies.

Runs on-chain programs

An sBPF virtual machine executes programs compiled by toly's lean-svm, locally, and meters them exactly as Agave does.

Lets programs call programs

Cross-program invocation with derived-address signing. The SPL Token and Token-2022 programs run unmodified; the system program is built in.

Runs Anchor programs

Both calling conventions, C and Rust. An Anchor vault that runs five programs in one instruction prints exactly what Agave's own runtime prints.

Applies whole transactions

Verifies the signatures, charges the fee, honours the compute budget, runs every instruction, enforces rent, and keeps all of it or only the fee.

Provides every sysvar

Clock, rent, epoch schedule, slot hashes and the rest, by system call, by address and as accounts, including a transaction's view of its own instructions.

Enforces the account rules

Only an owner changes an account's data or spends its lamports, read-only stays read-only, and lamports are conserved.

Exports what it learns

A JSON snapshot of every node, a JSON file that stays fresh, and Prometheus metrics over HTTP.

Keeps a stable identity

An optional key file makes a long-running node the same node after a restart.

Compiles other programs

leanc is a general compiler for its subset of Lean. Hello world is four system calls, start to finish.

Agrees with official Lean

The official toolchain type-checks every file, and must match leanc on every test program's output.

Builds reproducibly

The published binary and a build on your machine have the same SHA-256.

Survives hostile input

The parsers are bounds-checked and fuzzed with 16,000 random and corrupted records on every commit.

Limitswhere the line is

What it is not

Not a validator

It does not download blocks, replay transactions or vote. It observes and verifies the gossip plane.

Listen-only

It answers pings but does not yet serve or push records to other nodes.

Transactions, not blocks

It applies signed transactions to accounts you give it. It does not hold the ledger, and stake, vote and the loaders are not among its built-in programs.

Nothing is sent on-chain

Programs execute locally. The client does not build, sign or submit transactions.

x86-64 Linux

The code generator and the system-call numbers are specific to it.

A subset of Lean

No type classes, lambdas or polymorphism. The compiler does not check proofs; official Lean does that.

Roadmapintentions, not dates

From observing the network to following the chain

Each step moves the client closer to checking the ledger itself instead of listening to what other nodes say about it. On-chain programs are written in Lean with toly's lean-svm, which compiles Lean 4 to sBPF. This project is the other side: the node, and the machine that runs those programs.

cd lean-Solana-client
make && ./build/leansol   # no compiler needed
